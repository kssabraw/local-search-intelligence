# 0004 — One shared foundation; surfaces added sequentially

All four observation surfaces ride on a single shared foundation (canonical universe, `provider_task`/`raw_observation`, canonical entity graph, `api_usage` cost ledger, methodology versioning, unified scheduler/job contract) — never parallel per-surface stacks — and surfaces are built **in sequence**: Maps + Organic first (they prove the foundation on the cheapest, most structurally-settled capture), then AIO, then ChatGPT. Building the SERP surfaces first makes each later surface's foundation nearly free and de-risks the shared spine before taking on AIO's placement/card parsing and ChatGPT's harder vendor capture.

## Consequences

- Stage 1 delivers the shared foundation scoped to what the Maps/Organic pilot exercises — designed for extension, but not the full parent table catalog speculatively.
- Enrichment, transitions, findings, Strategy Evidence, and Client Mode are out of the current stages regardless of surface.
- Reprioritizing a surface earlier is possible but forfeits this de-risking order.
